ReAct

2023年的ICLR论文，第一作者是现在的腾讯首席科学家尧舜禹

整体IDEA是这样的：

Thought -> Act -> Observations -> Thought -> Act -> Observations -> ...

可以看到其和 CoT (Chain of Thought) 还是有差距的，CoT不进行Act，也就是不从环境获得反馈，而 ReAct支持从环境获得反馈以进行更全面的思考

Thought1 -> Thought2 -> ... -> Answer

但这个IDEA也不是完美的，实验表明在某些任务 ReAct 的泛化性能没有 CoT 好（CoT推理闭环，但容易产生幻觉；ReAct可以借用外部资料完善推理，但有时候搜不到/报错，影响结果），并且 CoT 的采样次数也对最后结果有影响，最后实验表明**ReAct -> CoT-sc(同一个问题用相同的temperature进行多次采样)**的效果是最佳的

但有一个很有趣的现象，对Palm（Gemini前身）直接进行 Zero-shot 或者 Few-shot 而不做微调，ReAct效果最差；但使用少量数据进行微调过后，效果是这样的

Palm6B(finetune) > Palm62B(Zero-shot or Few-shot)

Palm62B(finetune) > Palm540B(Zero-shot or Few-shot)

个人认为这篇文章仅仅是提示词工程，可能故事讲得好就中了吧

斯坦福小镇

提出一个架构，包括：

  • 记忆流：从相关性、重要性、新鲜度对记忆进行存储和检索
  • 反思：将记忆合并成高层次的推论，存入记忆
  • 规划：将记忆和反思结果转换为行动计划，存入记忆

Memory（每个事件都存，后续要使用的时候进行检索） 和 Reflection 的存在必要性很好理解，但是 Planning 就有点反直觉，我是这么理解的：

Planning 生成高层的全天计划，并且支持递归生成小时、分钟级别的计划，还支持动态重规划（若发生的事件打乱现有计划则重新生成计划）

且计划也是记忆的一种，也会被存储到记忆流中

感觉更像是一个博眼球的工程项目，而非科技研究

Reflexion

也是一篇非常经典的工作，提出的是语言式强化学习（太会包装了），直白点就是LLM总结然后把总结的话塞到记忆里面去，但是这个工作也解决了之前论文的痛点：反思无法实现跨轮完整闭环，失败记忆无法长期留存

论文把架构拆分为三个解耦的组件：Actor、Evaluator、Self-Reflection

且已有记忆分层的雏形，short-term存轨迹记忆（原始经历），long-term存自然语言反思文本，但其长期记忆存储是有上限的（防止超过LLM上下文），因为其不做检索，进行记忆读取时是全量塞进Prompt

Toolformer

为了解决模型调用外部工具需要大量人工标注、任务局限性的问题，这篇文章提出了Toolformer框架，主要是通过 SFT 对已有模型进行微调，而使用的数据则是被精心处理过的

如何获取高质量数据集而无需人工标注？离线构造

因为有多种类型的工具，每个工具只需提供几个调用样本用于告知LLM格式示例，让LLM自己筛选生成工具调用，然后筛选有用的工具调用，得到增强数据集

论文提到 <API>、</API> 与 -> 是特殊token

整体构造流程分为：

  • 离线阶段：纯文本CCC经过自动生成和筛选得到增强数据集C∗C^*C∗
    • 提示词只有每种工具的少量少样本示例，输入提示词，对每个token进行预测，得到模型生成 <API> 的概率，若概率超过阈值，则纳入候选调用，若最后候选调用个数超过k个，保留概率最高的前k个，其余丢弃
    • 在选中的位置构造提示词与位置之前的文字，让模型生成API调用，格式示例在提示词里面有，且一个位置最多只有m次API调用
    • 然后便是执行Tool，获得候选文本，格式为[Tool(输入) -> 工具输出]
    • 最后要对候选调用进行进一步筛选，那么如何评判哪些调用是有用的呢，作者定义了加权损失，距离API调用文本越近，权重越高，且这个损失是无监督损失（LM损失），选择真实token的预测概率作为损失，用于衡量模型对真实输出的自信程度
    • 同时作者定义了两种不同类型的baseline，一种是空文本，不插入任何API，纯原文写作下的损失；另一种是只写工具调用，但不给调用结果。最后选择损失相对低的那个作为基准用于对比，即Li−L_i^{-}Li−​
    • 而Li+L_i^{+}Li+​是插入完整工具（提问+返回结果）后的损失，损失更小
    • 最后的筛选条件为Li−−Li+≥τfL_i^{-} - L_i^{+} \ge \tau_fLi−​−Li+​≥τf​，若差值够大，则说明工具给的信息极大降低写作难度，可以保留
  • 在线阶段：使用增强数据集对模型进行微调，后续预测时遇到 -> 则调用API得到结果

LongMemEval

这个文章被ICLR2025接收，做的工作是关于Agent MEMORY的 主要贡献我觉得可以分为两点：一个是提出了一个全新的Benchmark，覆盖了五个主流方向（信息提取，多会话推理，时间推理，知识更新、拒答）；另外一个就是提出了新的记忆设计方案：抽取记忆变为fact，并与embedding后的向量共同变为key，虽然会丢失上下文，但是可以提升召回率；以轮次为最小粒度而不是会话来存储记忆，提升多会话推理的准确率；将记忆与时间戳绑定，同样提升了记忆的召回率；即使召回率非常高，但是模型如果不会用这些记忆，QA的结果也会很糟糕。作者使用chain-of-note，让LLM使用记忆的时候写一个note，减少幻觉和将记忆转换为JSON格式两种方法，提升QA准确率

Benchmark是如何构建的：

  • 人类专家人工设计所有问题和答案，并写出证据陈述（可以从哪些地方找到问题答案）
  • LLM根据第一步产生的结果生成聊天记录，生成完毕后由人工进行编辑和校对
  • 根据需要的会话长度自由拼凑第二步产生的聊天记录，有两种类型：S、M
